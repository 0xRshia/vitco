# تحویل تغییرات رابط کاربری ویتکو

این مجموعه برای بازبینی از شاخه `frontend-arad` به `main` آماده شده است.
ادغام و استقرار با مسئول مخزن و سرور است؛ در این مرحله سرور اصلی تغییر نمی‌کند.

## تغییرات پنج مرحله

۱. هماهنگ‌سازی نام و نشان ویتکو، رنگ‌ها، فونت فارسی، دکمه‌ها، کارت‌ها، ورودی‌ها،
پوسته روشن/تیره و نوار پایین موبایل.

۲. بازطراحی خانه و پروفایل، نمایش امتیاز واقعی، سفارش‌های اخیر، حالت مهمان و
حالت خالی، جستجو و ویرایش پروفایل با API موجود.

۳. هماهنگ‌سازی منو، انتخاب اندازه و افزودنی محصول، سبد، تخفیف و امتیاز، دریافت
زمان‌بندی‌شده، تأیید سفارش و پیگیری وضعیت؛ حفظ محاسبات معتبر سمت سرور و پرداخت
حضوری یا هنگام تحویل.

۴. نقشه تعاملی Leaflet/OpenStreetMap با مختصات ثبت‌شده، انتخاب موقعیت آدرس و
کافه، تقویم فارسی رزرو، نمایش ظرفیت واقعی و حفظ کافه/روز/ساعت/تعداد پس از ورود.

۵. ارتقای Next.js به 16.4.3، رفع هشدارهای گزارش‌شده وابستگی‌ها، بررسی تنظیمات
سرویس‌ها بدون افشای کلیدها، و اصلاح تشخیص تنظیمات خالی پیامک و ایمیل.

هیچ تغییر ساختار دیتابیس یا مهاجرت جدیدی در این مجموعه وجود ندارد. تغییرات
سمت سرور محدود به نام‌گذاری ویتکو و تشخیص تنظیمات خالی سرویس‌هاست؛ ارتقای
چارچوب نیز باید توسط مسئول سرور بازبینی شود.

## شواهد و محدودیت‌ها

- ساخت production، TypeScript و ۱۳ تست موفق بودند؛ `npm audit` صفر آسیب‌پذیری
  گزارش کرد. نتیجه بررسی روز آماده‌سازی در `release-readiness.md` ثبت شده است.
- ۲۷ مسیر در دسکتاپ و مسیرهای اصلی در موبایل بررسی شدند. خرید و رزرو در
  پایگاه جداگانه آزمایش شدند؛ اطلاعات آزمایشی وارد پایگاه اصلی نشده‌اند.
- مجموعه مستقل `test:e2e` در این مرحله اجرا نشده است. بررسی قالب‌بندی سراسری
  مخزن در ۲۱ فایل هشدار قبلی/تولیدشده خودکار دارد؛ فایل‌های این مجموعه جداگانه
  بررسی شده‌اند و بازقالب‌بندی عمومی انجام نشده است.
- تطبیق پیکسلی فیگما، توکن‌های دقیق و دارایی لوگوی نهایی به دسترسی فایل وابسته‌اند.
- کافه واردشده از ویترین کافه فقط قابل مرور است؛ امکان فروش و رزرو برای کسب‌وکار
  واقعی باید توسط حساب صاحب کافه و داده واقعی آن فعال شود.
- فایل‌های env، پایگاه داده، فایل‌های بارگذاری‌شده، داده‌های آزمایشی، خروجی ساخت
  و اسکرین‌شات‌های محلی جزو تحویل Git نیستند.

## چک‌لیست آرشیا پیش از ادغام و انتشار

- [ ] رابط‌ها و تغییرات API/احراز هویت را با تقسیم کار پروژه بازبینی کند.
- [ ] تغییرات Next.js و lockfile را بررسی و با `npm ci` نصب و build کند.
- [ ] `npm run typecheck`، `npm run test` و `npm run build` را اجرا کند و
      محدودیت‌های گزارش‌شده بررسی مرورگر و قالب‌بندی را ببیند.
- [ ] قبل از انتشار از SQLite و فایل‌های بارگذاری‌شده به شکل سازگار با WAL
      پشتیبان بگیرد و فضای ذخیره‌سازی پایدار یک سرور Node را حفظ کند.
- [ ] `APP_ORIGIN` دامنه اصلی HTTPS و مسیر پایگاه داده را در محیط خصوصی تنظیم
      کند؛ `npm run check:readiness -- --production` را اجرا کند.
- [ ] پرداخت حضوری را مطابق تصمیم فعلی حفظ کند؛ درگاه آنلاین اضافه نشده است.
- [ ] اگر بعداً پیامک یا بازیابی ایمیل لازم شد، متغیرهای کاوه‌نگار/Resend و
      فرستنده معتبر را خصوصی تنظیم و تحویل واقعی را با گیرنده مجاز بررسی کند.
- [ ] مختصات، منو، ساعات و ظرفیت کافه واقعی و تناسب سرویس نقشه با ترافیک را بررسی کند.
- [ ] پس از تأیید، PR را در `main` ادغام و نسخه جدید را روی سرور منتشر کند؛
      ورود، خرید، رزرو، نقشه و نمایش موبایل را در دامنه اصلی بررسی کند.
